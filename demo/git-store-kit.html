git-store-kit

Notes kept as JSON files in GitHub repos, one file per note, every save a commit. The page runs against a fake GitHub in the page, so nothing leaves it and the tokens below are made up; it starts over when you reload. The module comes from ../git-store-kit/, the branch this page was served from.

        Try the token setup

        The public repo reads without a token. The private one, and every save, needs one.

        1. From the repos says GitHub shows demo-team/notes-private only with a token.
        2. Tap Add a token next to it. The panel opens at that repo’s token field.
        3. Copy a demo token:
          Write, both repos
          Read only, the private repo

        4. Paste it in the field and tap Save token.
        5. See it load: the secret note appears.
          Write token: You can edit, Remove on the note, and the repo under Publish to.
          Read-only token: Read only, and nothing to publish to there.

        A real token is made on GitHub: the panel’s How do I make a token? says how.

        Other things to try

        Then publish or save that note: the panel asks whether to overwrite, keep theirs or save a copy. Restoring an old version from the working folder’s History asks too, because it saves on top of the version you opened.

        A default source, read from its index

        demo-team/starter is in the store’s defaults: followed on your first visit. Its git-store-index.json lists its notes, so it loads with no API requests (see Requests sent). Remove it in Sources and tokens and reload: it stays removed.

        The fake GitHub keeps its repos in this tab through a reload (fake.export() into sessionStorage, createFakeGitHub({state}) back), the way a practice mode can.
